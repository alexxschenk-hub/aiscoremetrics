The most important question before buying hardware: does my model fit in memory? If not, it either won't run at all or crawls. The good news: you can estimate the requirement quite accurately with a simple formula.

The formula

Memory (GB) ≈ parameters (billions) × bits per weight ÷ 8 + KV cache (grows with context) + about 1 GB runtime overhead

With the standard quantization Q4_K_M (about 4.85 bits per weight) the rule of thumb is: 0.6 GB per billion parameters, plus context and overhead.

Example Qwen3.6 27B: the model file is 17.0 GB at Q4_K_M. At 32,000 tokens of context, add 1.9 GB of KV cache, plus 1 GB overhead – about 19.9 GB. That fits on a 24 GB graphics card, but not on a 16 GB one.

Quantization: fewer bits, less memory

Quantization stores each weight with fewer bits. That saves memory and makes the model faster, at a small cost in quality.

  • FP16 (16 bits): full precision, 2 GB per billion parameters – rarely sensible locally.
  • Q8_0 (8.5 bits): practically lossless, about 1.1 GB per billion.
  • Q4_K_M (4.85 bits): the default. Barely noticeable quality loss, about 0.6 GB per billion.
  • Q3 / Q2: only as a last resort – quality drops noticeably.

Rule of thumb: a larger model at Q4 is almost always better than a smaller one at Q8.

Context: the underrated memory hog

Every token in context takes space in the KV cache. How much depends heavily on the architecture: for Llama 3.3 70B, 32,000 tokens cost about 10 GB extra; for Qwen3.6 27B, thanks to leaner attention, only 1.9 GB. If you want to process long documents or whole code repositories, plan a few gigabytes of headroom. The calculator has a context slider from 4k to 128k.

Bandwidth: why fitting isn't enough

Memory decides whether a model runs – memory bandwidth decides how fast. For every new token, the active weights have to be read once in full:

tokens/s ≈ efficiency × bandwidth (GB/s) ÷ active weights (GB)

Example: an RTX 4090 has 1,008 GB/s. Qwen3.6 27B reads about 17 GB per token → roughly 0.6 × 1,008 ÷ 17.4 ≈ 35 tok/s.

MoE models (mixture of experts) are the trick to make large models fast: Qwen3.6 35B-A3B needs memory for all 35 billion parameters but reads only about 2 GB per token. So on the same card it writes many times faster than a dense 27B model.

If a model doesn't fully fit in graphics memory, part of it can spill into PC memory. But regular DDR5 only manages about 60 to 90 GB/s – speed then drops many times over.

Special case: Macs and mini PCs

Macs, the DGX Spark and mini PCs with Ryzen AI Max share memory between CPU and GPU. That makes very large models possible, but not all of it is usable: by default macOS gives the GPU only about 67% (up to 36 GB) or 75%. A 96 GB Mac therefore has about 72 GB for the model; with the limit raised it's about 90 GB. More in the comparison RTX 5090 vs Mac Studio M5 Ultra.
